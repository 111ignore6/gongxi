# 后端体验改进：与前端重构的接口边界

本轮由组织者分工：DSH 负责前端设计与重构，Codex 负责后端设计，并协作验收。后端保留单工作区、独立身份和统一 HTTP 协议，不引入模型托管或厂商适配层。

## 具体问题与选择

1. 当前收到事件后重新请求完整 state，所有议题的历史正文随之重复传输。增加可选轻量 state 与议题历史分页，旧客户端默认行为不变。这个改动仅提供能力；前端采用前不能声称界面已经减少了传输或重绘。
2. 方向发布已有版本条件，任务变更此前没有旧状态校验。增加可选 expected_updated_at，让新客户端在并发调度时得到明确409。后端在原来的写事务内完成校验和更新；权限规则不放宽。旧客户端仍可按原方式操作，不能声称所有客户端都已受保护。

具体字段与错误行为以 [实现合同](IMPLEMENTATION.md) 为准。消息分页使用存储顺序的位置，与事件消费cursor分开；页面内部仍按创建顺序展示。SQLite增加议题索引，现有数据库启动时自动建立，不重写现有消息或身份。

## 前端接入顺序

- 前端可先继续使用原state完成布局重构，不依赖后端重启。
- 采用分页时，先请求轻量state、再读取当前议题最新页；读取旧页时前插并保留视觉锚点，按消息id去重。
- 收到事件仍按事件协议处理。重新读取最新页不会补齐任意数量的中间新消息；如本地断连期间积累超过一页，必须明确补齐或重置当前消息窗口，不能静默跳过。第一轮不提供after接口，不能假装已支持无界增量合并。
- 任务操作传入所见updated_at；遇409保留用户意图、刷新任务并提示重新确认，不自动重试覆盖。
- 原完整state与导出保留，单议题分页不改变所有成员可读整个空间的既有权限语义。

## 验证与运行边界

新增真实HTTP测试覆盖：跨议题分页隔离、分页期间追加、完整与轻量state区别、空列表、非法游标/页长、鉴权、任务条件成功与冲突、冲突不产生事件及旧客户端兼容。测试创建独立数据与服务，不使用真实会议的组织者身份。

源码变更不会更新正在运行的后端进程。开发与验收使用隔离实例；正在讨论的4284不因测试而重启。正式载入新版前，应先完成前后端约定和回归验证，再与组织者协调短暂重启窗口。

## 暂不扩大范围

每个请求仍使用既有SQLite事务并更新last_seen_at；目前没有证据支撑并发容量结论。数据库模块拆分、只读连接优化、事件流推送、附件、全文检索与更多角色需要独立需求和测量，不随此次界面重构一起堆入。
