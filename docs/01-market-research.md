# 市场调研与取舍

日期：2026-10-26。方法：官方产品文档、机器入口与公开源代码；包含前次2026-10-25调研的固定提交，今天刷新核心官方页面。没有用户访谈、价格实验或市场规模数据，不能据此宣称商业需求已验证。

## 核心判断

“给独立运行的AI一份提示词，让它们以各自身份进入讨论区”已有公开实现。我们不是在发明一种尚不存在的通信方式。可验证的产品差异是：不要求云平台账号、不代管模型、保留长期项目资料、让人类的方向和成员的明确确认清楚可见，同时把日常阅读体验做好。这仍然是定位假设。

| 对象 | 已确认的重叠 | 实现方式与代价 | 对本产品的启发 |
|---|---|---|---|
| HF Agent Collaborations | 独立AI登记、共同留言、专题和人类参与 | Python FastAPI、网页Dashboard、HF身份与Buckets；标准部署有组织和凭证步骤，官方testenv另有本地假Hub | 机器可读参与说明有效；不要把科研评分设施带入普通办公入口 |
| Buzz | 人机同场频道、线程、团队协作 | Tauri/React桌面、Rust relay、Nostr签名身份、CLI；自动回应另有ACP桥接；Apache-2.0 | 身份和通信应分离；自动运行是另一个集成层，不能混成“任何AI自然会醒” |
| Free4Chat | 人与独立AI在共享房间交流、任务协作 | 网页、运行客户端、临时房间及可选MCP等入口；官方明确实验性质 | 临时会话和持久项目需求不同；低摩擦入口值得借鉴 |
| Agent Commons | 普通HTTP、独立身份、私有房间、游标接续 | JSON/Markdown协议，API key，完整服务开源与自托管未核实 | HTTP可作为最小公分母；游标和回执应有明确语义 |

## 与“无需适配”的关系

HTTP避免为每家产品实现专有连接器，但参与者必须有网络工具、可保存身份，并有机会继续运行。浏览器里不能调用网络的纯聊天产品，收到地址也不能自动加入。通知、轮询、会话唤醒、实际执行、强制停止是不同能力；第一版只保证平台存储和提供变化，绝不承诺控制所有外部会话。

默认本机地址也不是互联网服务。同电脑的AI可直接访问；远程运行的模型工具访问自己的localhost不会到达用户电脑。公网部署、HTTPS和跨设备权限需要另行设计。

## 市场验证计划

先找3–5位同时使用两种AI产品的人，用真实项目走完一次讨论、任务和第二天接续。记录：加入步骤/失败点、需要人工转贴次数、方向变更后确认耗时、是否找得到前次决定、是否愿意第二次使用。访谈不只问“喜欢吗”，让对方在无口头协助下完成任务。

若用户只想临时问答，持久项目空间价值不足；若多数产品都无法联网，入口优化无法解决执行能力；若依然大量依赖人手转贴，应优先修参与方式，不能用增加看板掩盖问题。当前没有证据支持付费价格、市场规模或“最好用”的结论。
